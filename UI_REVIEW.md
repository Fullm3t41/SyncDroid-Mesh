# UI review — 1.2.15 testing candidate

Reviewed Android (SyncDroid-Mesh), Windows (SyncDows), and macOS (SyncTosh). Linux currently has a planning document rather than an implemented app. This review covers the current source, not previously published installers.

## Changes made

| Area | Finding | Result |
| --- | --- | --- |
| Desktop pairing | Pasting a complete code into the individual digit boxes lost digits; keyboard submission was awkward. | One labeled input accepts a complete code, spaces from copied codes, edits, and Enter. Incomplete codes, lockout, and busy state prevent submission. |
| Android pairing | Clearing the native input could leave the previous code in Compose state. Repeated taps could start concurrent joins. A discovery timeout could leave a searching status. | Input listeners read current state, one join runs at a time, Back cancels that attempt, and discovery timeout gives a retry instruction. |
| Pairing expiry | Expired codes remained visible or had a fixed lifetime label. | Codes have a live expiry indicator and disappear when expired, with instructions to generate a replacement. |
| First run | The Sync screen did not offer an obvious setup action. Desktop folder creation allowed entry before the required mesh existed. | Setup actions are on Sync. Desktop Add is disabled until a mesh exists, with an explanation in the empty state. Android offers Pair a device when there are no peers. |
| Desktop layout | At 420 dp and 150% text size, the Sync heading could collapse to zero width. | Heading and wrapping actions occupy separate rows. Several form dialogs now scroll. |
| macOS mesh diagram | Names could clip inside a fixed circle; online peers showed only initials. | Uses the measured diagram layout already in SyncDows, with separate full names and status labels. A layout test covers 0–64 peers, narrow windows, and enlarged labels. |
| Android navigation | System Back did not navigate secondary screens or traverse the folder picker. | Back returns through settings and folders, clears file selection before leaving, and cancels pairing. Folder removal prevents navigation while running. |
| Desktop device management | Removal was hidden behind right-click. | Each peer has an accessible options button. Removal still requires confirmation; Cancel leaves the device untouched. |
| Desktop status and settings | A saved mesh was described as online without any nearby peer. About appeared clickable without an action. macOS referred to a notification bar. | Status distinguishes setup, waiting, and nearby peers; About is static information; macOS says menu bar. |

## Verification

| Target | Result | What ran |
| --- | --- | --- |
| Android | 120 passed; debug APK built | Existing unit tests and 3 new Compose/Robolectric UI regressions on simulated API 35, using native graphics. |
| Windows app | 83 passed | Existing tests plus 11 Compose UI tests under Xvfb on Linux. |
| macOS app | 85 passed | Existing tests plus 12 Compose UI tests and the mesh-layout regression under Xvfb on Linux. |
| Shared protocol/core | 85 passed; 1 skipped | Protocol and sync-core tests. The optional release-network smoke test was skipped. |
| macOS updater | 6 passed | Python installer/update tests. |

The desktop interaction tests cover pasted/cleared pairing codes, Enter, incomplete input, lockout, duplicate submission, expired offers, both first-run actions, folder setup gating, device removal and cancellation, chat send/clear, appearance, and settings actions. UI callback tests establish that the correct action is invoked; they do not establish delivery to another device.

Desktop rendering covers Sync, Folders, Devices, Chat, Settings, Cloud sync, Background operation, Power & discovery, and File history in light and dark themes. Narrow-window checks use 420 dp with 150% text size. Android regressions cover clearing the native code input, disabling input while joining, and traversing a child folder with system Back. Android rendering was inspected for pairing in both themes and a nested folder picker.

Screenshots are generated by the tests in:

- `apps/windows/build/ui-review/`
- `apps/macos/build/ui-review/`
- `apps/android/app/build/ui-review/`

Cross-platform CI now uploads these screenshots and test reports. Those native CI jobs have not been run as part of this local review.

To reproduce, run `./gradlew --no-daemon test` in each desktop project and `./gradlew --no-daemon testDebugUnitTest assembleDebug` in `apps/android`. On Windows, use `gradlew.bat`. Desktop UI tests on a headless Linux host need a display, for example `xvfb-run -a ./gradlew --no-daemon test`. Android's first Robolectric run downloads its Android runtime; a restricted cloud host must pass its proxy/trust-store configuration to the test JVM and allow the Maven repository.

## Remaining verification and product gaps

- **Native OS behavior is pending:** Windows installation/uninstallation, upgrade and data preservation, file pickers, touch keyboard, firewall prompts, tray/menu-bar behavior, launch at login, macOS permissions, and signed updates. The separate Windows installer changes include a disposable-machine CI smoke test, but no Windows machine was available here.
- **Real multi-device workflows are pending:** pairing and approval, discovery on Wi-Fi, file transfer, chat delivery/attachments, offline recovery, conflict resolution, and reconnection. Existing automated tests cover parts of these systems; they do not replace a Windows–macOS–Android device run.
- **Cloud sign-in is pending:** Google Drive and OneDrive need configured release credentials and real accounts/devices. Scope and account controls were rendered; OAuth and remote transfer were not exercised.
- **Android live-device behavior is pending:** permissions, keyboard visibility, background service, storage providers, and gesture navigation. An API 36 emulator without hardware acceleration eventually booted but showed system-service hangs and timed out during installation. It did not produce a successful live-app check. Robolectric checks are reported separately above.
- **macOS feature gaps remain:** SyncTosh does not currently expose Windows' Leave mesh or global overwrite-only exception settings. These require runtime/store work beyond the UI fixes made here; the review does not imply feature parity.

The passing checks support the specific flows above. They are not a certification that every function works on a fresh native installation. The Windows install log from the reported new-PC failure is still needed to identify that particular failure.
